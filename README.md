# YAQIN CODE | پورتفولیو (React + Vite + React Router)

اجرا: `npm install` و بعد `npm run dev`      ساخت نسخه نهایی: `npm run build`

## هر چیزی کجاست؟

| می‌خواهم... | این فایل یا پوشه را باز کنید |
|---|---|
| متن‌های فارسی را عوض کنم | `src/data/text.fa.js` |
| متن‌های انگلیسی را عوض کنم | `src/data/text.en.js` |
| پروژه یا مهارت اضافه، ویرایش یا حذف کنم | پنل مدیریت: `#/admin` (بخش «بک‌اند» پایین) |
| لینک واتساپ، تلگرام، گیت‌هاب | `src/data/socials.js` |
| رنگ‌های روشن و تاریک | بالای `src/styles/base.css` |
| لوگو و عکس | `public/logo.jpg` و `public/photo.jpg` |
| عکس پروژه‌ها | در پنل مدیریت آپلود کنید |

## هر بخش یک پوشه دارد (کد + ظاهر کنار هم)

```
src/
  data/                 همه متن‌ها و اطلاعات (بدون کد)
  styles/base.css       رنگ‌ها، دکمه‌ها، شبکه کارت‌ها
  components/           چیزهایی که در چند جا استفاده می‌شوند
    Header/  Footer/  Card/  InfoCard/  ProjectCard/  Icon/  ScrollToTop/
  pages/                هر آدرس یک صفحه
    Home/               صفحه خانه + sections/ (Hero, Stats, Services, FeaturedProjects, Process, CallToAction)
    About/  Projects/  ProjectDetails/  GitHub/  Contact/  NotFound/
  App.jsx               آدرس‌ها (Route) و زبان و حالت روشن/تاریک
```

مثال: می‌خواهید ظاهر بخش «روش کار من» را عوض کنید؟ پوشه `pages/Home/sections/Process` و کارت‌ها: `components/InfoCard`.

## دکمه‌ها چطور کار می‌کنند؟

- دکمه **جزئیات** هر کارت به `#/projects/<id>` می‌رود. `id` را در `data/projects.js` می‌نویسید.
- دکمه **مشاهده سایت** فقط وقتی می‌آید که `link` پروژه خالی نباشد.
- صفحه تازه: یک پوشه در `pages` بسازید و یک `<Route>` در `App.jsx` اضافه کنید.

## صفحه گیت‌هاب

مخزن‌ها هنگام باز شدن صفحه، زنده از گیت‌هاب گرفته می‌شوند (بیشترین ستاره اول). لیست چند دقیقه در مرورگر نگه داشته می‌شود تا گیت‌هاب درخواست‌ها را محدود نکند.

## اینترنت ضعیف یا قطع

- اولین باز شدن: به‌جای صفحه سفید، یک چرخنده دیده می‌شود. فونت بعداً می‌آید و تا آن موقع Tahoma نشان داده می‌شود.
- بعد از اولین بازدید، سایت در مرورگر ذخیره می‌شود (`public/sw.js`) و با اینترنت ضعیف یا قطع هم باز می‌شود. این فقط در نسخه نهایی (`npm run build`، یا همان Vercel) کار می‌کند، نه در `npm run dev`.
- اینترنت قطع شود: نوار «اینترنت قطع است» پایین صفحه می‌آید.
- صفحه گیت‌هاب: «در حال دریافت...»، بعد از ۸ ثانیه «نشد + تلاش دوباره»، و با وصل شدن اینترنت خودکار دوباره تلاش می‌کند.
- خطای غیرمنتظره: صفحه سفید نمی‌شود، پیام و دکمه «بارگذاری دوباره» دیده می‌شود.
- بعد از تغییر بزرگ در سایت، عدد `VERSION` در `public/sw.js` را عوض کنید.

## بک‌اند و پنل مدیریت

یک سرور هم خود سایت را نشان می‌دهد هم API و پنل را. Node.js و SQLite، **بدون نصب هیچ بسته‌ی اضافه** (فقط Node نسخه ۲۲.۱۳ یا بالاتر؛ هشدار `ExperimentalWarning` هنگام اجرا بی‌خطر است).

### روی کامپیوتر خودتان

```
npm install
npm run dev
```

سایت روی `http://localhost:5173` بالا می‌آید و بک‌اند هم خودکار با آن اجرا می‌شود. بار اول:

1. پروژه‌ها و مهارت‌های فعلی خودکار داخل دیتابیس می‌روند.
2. در ترمینال یک **کد راه‌اندازی** چاپ می‌شود. به `http://localhost:5173/#/admin` بروید، نام کاربری، رمز (حداقل ۱۰ حرف) و آن کد را بزنید تا حساب مدیر ساخته شود. (این فرم فقط تا وقتی هیچ ادمینی نیست کار می‌کند.)

بعد از ورود، **خود سایت را می‌بینید** و بالایش یک نوار «حالت مدیر» است: روی هر کارت پروژه دکمه‌ی «ویرایش» هست و «+ پروژه‌ی تازه» همیشه در دسترس است. هر چیزی که ذخیره کنید همان لحظه در سایت دیده می‌شود.

### انتشار روی Render

راهنمای قدم به قدم و فایل `render.yaml` آماده است: **`RENDER.md`**.

### انتشار (روش ساده: یک سرور، هر میزبان)

```
npm run build
npm start
```

سرور خود سایت (پوشه‌ی `dist`) و API را روی یک آدرس می‌دهد؛ CORS و `VITE_API_URL` لازم نیست. روی میزبان (Render، Railway، Fly.io، VPS) این‌ها را بگذارید:

| متغیر | معنی |
|---|---|
| `NODE_ENV` | `production` |
| `SESSION_SECRET` | رشته‌ی تصادفی حداقل ۳۲ حرفی (اجباری) |
| `DATA_DIR` | پوشه‌ی دیتابیس و عکس‌ها؛ باید **دیسک ماندگار** باشد، وگرنه با هر دیپلوی همه‌چیز پاک می‌شود |
| `TRUST_PROXY` | `1` (پشت پروکسی میزبان) |
| `ADMIN_USERNAME` و `ADMIN_PASSWORD` | اختیاری: ادمین را بدون فرم مرورگر می‌سازد. وگرنه کد راه‌اندازی در لاگ سرور چاپ می‌شود |

دستور ساخت: `npm install && npm run build`. دستور اجرا: `npm start`. نمونه‌ی همه‌ی متغیرها: `server/.env.example`.

### انتشار (روش دوم: سایت روی Netlify/Vercel، بک‌اند جدا)

در این حالت فرانت‌اند را مثل قبل منتشر کنید و در تنظیمات آن `VITE_API_URL` را برابر آدرس بک‌اند بگذارید. در بک‌اند `ALLOWED_ORIGINS` را برابر آدرس سایت بگذارید. مزیتش این است که اگر بک‌اند خاموش شد، سایت همچنان کار می‌کند.

### اگر بک‌اند خاموش شد

سایت هیچ‌وقت صفحه‌ی خالی نشان نمی‌دهد: اول آخرین اطلاعات ذخیره‌شده در مرورگر یا نسخه‌ی داخل سایت (`src/data/snapshot.json`) نمایش داده می‌شود و اگر بک‌اند جواب داد، جایگزین می‌شود. فرم تماس فقط وقتی دیده می‌شود که بک‌اند جواب بدهد. **قبل از هر انتشار** این را اجرا کنید تا نسخه‌ی داخل سایت با دیتابیس یکی باشد:

```
npm run export-fallback
```

### دستورها

| دستور | کار |
|---|---|
| `npm run dev` | سایت + بک‌اند برای توسعه |
| `npm run build` و `npm start` | ساخت و اجرای نهایی (یک سرور) |
| `npm run import-github` | پروژه‌های گیت‌هاب که عکس دارند را پیدا می‌کند، عکس را داخل سایت ذخیره می‌کند و پروژه می‌سازد (اینترنت لازم است) |
| `npm run setup-code` | کد راه‌اندازی اولین حساب مدیر را نشان می‌دهد |
| `npm run create-admin` | ساخت یا عوض کردن حساب مدیر از ترمینال (ورودهای قبلی باطل می‌شوند) |
| `npm run export-fallback` | نسخه‌ی پشتیبان داخل سایت را از دیتابیس می‌سازد |
| `npm run backup` | کپی دیتابیس (پوشه‌ی `uploads` را هم جدا نگه دارید) |
| `npm run test:server` | تست‌های بک‌اند |

### امنیت (خلاصه)

یک حساب ادمین؛ مسیر ثبت‌نام وجود ندارد. رمز با scrypt هش می‌شود، ورود ۸ تلاش در ۱۵ دقیقه محدود است، تغییر رمز همه‌ی ورودهای قبلی را باطل می‌کند. آپلود عکس از روی محتوای فایل بررسی می‌شود. فرم تماس محدودیت ارسال و تله‌ی ضدربات دارد. لینک‌های پروژه فقط `http` و `https` می‌پذیرند.
